#### 1. `usable_item_fraction` does NOT have the property CLAUDE.md credits it with, and the test file demonstrates that side by side without noticing

- **File:line**: `Brain/calibration/trial_skills.py:136-150`; tests
  `Brain/tests/test_trial_skills.py:102-118`
- **What is wrong**: The function's own docstring says *"A mega-blob split scores near zero
  here"*, and CLAUDE.md's skills section records it as the fix for the median's small-K blind
  spot (*"a mega-blob split cannot fool that"*). It computes
  `sum(size for g if size >= floor) / total`, so the 394-item blob is itself above the floor and
  **counts as usable**. The test named `test_a_mega_blob_split_scores_near_zero_usable_items`
  asserts `== approx(394/405) = 0.973`, i.e. it asserts *near ONE* under a name that says *near
  zero*, and the next test, `test_a_healthy_split_puts_most_items_on_usable_axes`, asserts
  `83/85 = 0.976`. **The pathological case and the healthy case score within 0.003 of each
  other.** The metric cannot separate the two situations it was built to separate (taxonomy
  item 5). The test's only assertion that actually discriminates —
  `sum(g["size"] for g in groups if 12 <= g["size"] < 100) == 0` — is arithmetic performed in
  the test itself over a literal list; it calls nothing in the module.
- **What number it corrupts, and in WHICH DIRECTION**: `usable_item_fraction` is **never called
  anywhere** — grep across the repo returns only its definition and its three tests; the report
  and `evaluate_window` use `n_skills` + `median_size` only. So no published number is wrong
  *today*. What is wrong is the recorded claim in CLAUDE.md that the median blind spot is
  guarded: it is not, by a dead function that would have **inflated** the apparent health of a
  one-blob-plus-singletons split to ~0.97 had it been wired in. Any future re-run of
  `trial_skills` that adopts this metric would read the documented failure shape as a pass.
- **Confidence**: certain (arithmetic, verifiable by hand from the test's own literals)
- **Cheapest way to verify**:
  `grep -rn "usable_item_fraction" Brain/ --include=*.py` → 1 definition, 3 test lines, 0 call
  sites; then read `Brain/calibration/trial_skills.py:136-150` against
  `Brain/tests/test_trial_skills.py:102-118`.

### CLEAN

Places I looked specifically and found nothing wrong. These do not need re-checking.

- **Fact 4 (the logging-singleton contamination) is FIXED and correctly fixed.**
  `tests/test_response_taxonomy_auto_pass.py:12-18` declares `_disable_real_log_file` with
  `@pytest.fixture(autouse=True)` at **module scope**, so it applies to every test in the file
  without opt-in — there is no test that can miss it. I checked every class
  (`TestJaccard`, `TestMatchTrackingRow`, `TestUpsertTrackingRow`, `TestResolvePrimaryTopicKey`,
  `TestAttemptGraduation`, `TestRunAutoPass`): all are covered. The `FileHandler` is still
  constructed at import time (`response_taxonomy_auto_pass.py:36-40`) so
  `Brain/logs/response_taxonomy_auto_pass.log` is *opened* by a test run, but with
  `_logger.disabled = True` nothing is written. `calibration/graduate_sink_topics.py` has no
  logger at all (`print` only), so `test_graduate_sink_topics.py` needs no equivalent guard.
- **`shared/head_to_head.py`'s rate arithmetic** — I checked `win_rate`, `swap_agreement`,
  `order_average` and `by_decile` for taxonomy items 2 (biased denominator) and 7 (two
  estimators as one number). `win_rate` excludes ties from the denominator and reports
  `n_total`, `n_decisive` and `tie_share` alongside, so the denominator is always printable;
  `swap_agreement` excludes double-tie items from `n` and reports `both_tie_share` separately;
  both return `None` rather than `0.0` on an empty denominator, and both behaviours are pinned
  by tests. `by_decile` recomputes `win_rate` per stratum with the same function, so point
  estimate and strata are one estimator. No defect.
- **`assign_swap_batches`** — the C1 memory-contamination guarantee (no batch holds both orders
  of one item) is not merely asserted on one example: `test_the_guarantee_holds_across_200_random_shapes`
  property-tests it over 200 random `(n, batch_size, seed)` combinations, also checking
  `len(flat) == 2n` and exact multiset equality. Duplicate ids raise. This is genuinely strong.
- **`derange` (arm B pairings)** — I checked for taxonomy item 1. The tests really do constrain
  no-fixed-point, permutation-ness (so each rubric receives equal attempts in B as in A1), the
  cosine rejection at `merge_cosine_threshold`, the honest `no_valid_partner_*` return instead of
  pairing anyway, and seed reproducibility. The `_sim` helper builds a symmetric matrix with a
  1.0 diagonal, which correctly makes self-pairing impossible independently of the fixed-point
  check. Nothing wrong here — the ceiling's asymmetry was in `_build_items`, not `derange`.
- **`shared/skills.py::cluster_behaviours` centroid renormalisation** — I checked
  `test_a_growing_group_keeps_a_unit_centroid` for the "would pass if the body were deleted"
  failure. Its docstring records that an earlier version using near-identical vectors did NOT
  catch the bug and that the current spread (`_unit(1,0,0)` … `_unit(1,0.45,0.45)` at threshold
  0.88) was chosen so the un-normalised running mean falls below the threshold while the true
  cosine stays above it. That is the right construction and the right reasoning.
- **`null_pairs` direction** — I checked whether `test_null_pairs_are_drawn_from_the_least_similar_behaviours`
  is vacuous. It is not: with `_A/_A_NEAR/_B/_C` the pool collapses to a single pair, and
  reversing the sort in `trial_skills.py:268` would select the 0.98-cosine pair and fail the
  `< 0.5` assertion. The direction is genuinely constrained. `null_groups` size-matching (the
  blinding property) is likewise really asserted.
- **`select_judge_thresholds` / `evaluate_window`** — I re-derived all four
  `POWER_STANDARDS` rows by hand and confirmed `meets_standard` requires **both** `n_skills <=
  max_k` **and** `median_size >= min_members`, with a test for each half failing independently.
  `evaluate_window` treats an absent validity as a fail (`v is None → continue`), pinned by
  `test_an_unjudged_threshold_never_counts_as_a_pass`. The 2026-08-13 "selected on K alone" hole
  is genuinely closed and genuinely tested.
- **`test_trigger_quality.py` enum literals** — checked for taxonomy item 4 (name that never

- **`test_response_taxonomy.py`'s embedder stub** — checked for fixture drift. The autouse

- **`test_naren_ceiling.py`'s aggregation tests** — `test_aggregate_keeps_the_same_milestone_id_separate_across_rubrics`
