### CLEAN

Stating these explicitly so the next person does not re-check them.

- **The weighted-score definition is consistent everywhere and the test is not circular.**
  I grepped every `(hits + 0.5*partial)/attempts` in the repo: `db/schema.sql:193`,
  `gap_output.py:19` (as the complement), `shared/rubric_validation.py:61`,
  `shared/coverage_areas.py:175-176`, `calibration/{score_naren_ceiling,measure_scoring_noise,
  trial_grader_inputs,trial_call_scoring,read_gap_reasons}.py`. All agree. The gap_output test
  re-derives the formula rather than calling the function under test, so it is a genuine
  independent restatement, not assert-X-after-mocking-X. **Taxonomy items 2 and 7 are clean here.**
- **Severity thresholds are not hardcoded-drifted.** The `_tuning()` literals (0.60/0.35/0.15)
  match `tuning.yaml`, *and* `test_severity_reads_the_shipped_thresholds` + `_tuning(...=0.30)`
  make the tests threshold-independent. This is the correct pattern and it is the opposite of the
  `test_ambiguous_trigger_keeps_the_near_ties` precedent I was asked to hunt for.
- **`test_similarity_mode_margin_governs_how_many_candidates_survive` does NOT bake in a threshold.**
  It passes `similarity_relative_margin` explicitly (0.90 and 0.999) against a fixed 0.60/0.59 pair,
  so it tests the rule rather than the shipped value, and it raises `max_scenarios_per_signal` to 2
  — which is necessary, because `relative_match.topk_pick` slices `candidates[:cap]` and the margin
  is provably inert at cap 1. This is the near-tie trap handled correctly.
- **`milestone_ids` positional-identity tests are real, not tautological.** They cover the v1
  missing-`order` KeyError, the duplicate-`order` PK collision, the migration guarantee
  (`M{order}` ≡ positional for a dense v2 rubric), and — critically — that neither
  `skip_uncoachable` nor `require_validated` renumbers survivors, asserted both in the returned ids
  *and* in the emitted prompt. Deleting the function body could not pass any of these.
- **`response_outcome` is derived from turn roles, not from the LLM, and the tests prove it.**
  `test_gemma_mode_response_outcome_derived_from_turns_not_llm` feeds a Gemma reply with no outcome
  field and asserts `other_joveo` from the turn roles. `classify_response_outcome`'s `start_index`
  is a list position and `EgoTrapTurn.index` is assigned as `len(turns)`, so the two coincide in
  both production and the fixtures — **taxonomy item 3 (numbering/base mismatch) is clean for these
  four files.** (The separate 1-based `format_transcript` boundary is correct and pinned by
  `test_transcript_is_one_based_and_numbers_every_turn`; the `+1` at the `kb_pairs` boundary lives
  in `trial_call_scoring.py:332`, another batch's file.)
- **`EgoTrapTurn`, `EgoTrapRole` and the milestone dict fixtures have NOT drifted.** `_turn()`
  supplies all five `EgoTrapTurn` fields; `EgoTrapRole` has exactly the three members the tests use;
  `_v2_milestone` carries all ten keys `v2/layer_c._finish_rubric` writes, and
  `_EVIDENCE_FIELDS` is fully covered by `test_evidence_captures_every_v2_field`. The one real
  fixture drift I found is the tuning fixture (finding 1) and the speaker-role vocabulary
  (finding 2).
- **No test in this batch asserts a mock's return value back to itself.** Every `mocker.patch` of
  `call_gemma` is followed by an assertion on *transformed* output (id reconciliation, verdict
  normalisation, positional ids, gating) or on the *prompt that was built*, which the mock does not
  supply. The closest to circular is `test_a_dict_wrapped_reply_is_accepted_like_the_batch_scorer`,
  and it still constrains the `isinstance(raw, list)` branch.
- **The `gap_events_enabled` gating test is not a boolean collapse.** It checks both arms
  (`insert_gap_event` not called / called once) *and* that the two aggregate writes still fire, so
  taxonomy item 8 does not apply.
- **`build_gap_record`'s hit/partial/miss partition is exhaustive and tested in all three
  branches**, including that `full_hit` produces no `gaps` entry — the one place a reader counting
  `len(gaps)` could be misled — and that a missing `evidence` key degrades to `{}` rather than
  raising.
